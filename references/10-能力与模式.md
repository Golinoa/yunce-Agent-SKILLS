# 能力与模式（第 2 步）

## 一、为什么先自检

同一个提示词，发给不同 AI，能力差别很大：

- 有的能跑代码、能把文件给用户下载 → **可以出 xlsx**；
- 有的只会输出文字 → **只能出 Markdown 表格**；
- 有的能写文件但装不了库 → **退一步出 CSV 也能导入**。

**先摸清能力，再选路径**——不要凭感觉承诺"我给你生成 Excel"，最后却给了一段文字。

## 二、怎么自检

### 能跑就跑（可选，**不是必须**）

> 🔴 本技能**以文本描述为主**。`scripts/` 是**可选加速器** ——
> 能跑就用（省事、产物更保真）；**跑不了完全不影响交付**，按文本自己产出即可。

```bash
python3 scripts/probe_capability.py
```

输出示例：

```json
{ "can_run_code": true, "can_write_file": true, "has_openpyxl": false,
  "template_local": true, "template_reachable": false }
VERSION=1.3.0
LEVEL=A
建议=走 A：用 assets/ 里的模板 → scripts/build_xlsx.py 填数据 → 交付 .xlsx
```

**看 `LEVEL=` 这一行即可。**

### 跑不了脚本时：手工三问

1. **我能执行代码吗？**（能不能跑 Python / 有没有代码执行工具）
2. **我能产出"用户可下载的文件"吗？**（不只是把内容打在对话里）
3. **我拿得到 `assets/` 里的模板吗？**（仓库在本地？能下载 raw 链接？）

## 二·补 · 第二道自检：`NET`（决定能不能"直接写入"）

`LEVEL` 只回答"**我能产出什么**"。还有一个**互相独立**的能力：**能不能真的发出 HTTP POST**。

> 读网页 ≠ 能发请求。很多 AI 能打开链接，但**没有任何办法向外发一个 POST**。

### 怎么测（一条命令：开场握手）

```bash
curl -s -X POST "{apiBase}/assist-import/hello" \
  -H "Content-Type: application/json" -d '{"promptToken":"{promptToken}"}'
```

- 成功返回（含 `sessionId`）⇒ **`NET=yes`** ⇒ 可以走「直接写进系统」
- 跑不了 / 报错 / 没返回 ⇒ **`NET=no`** ⇒ **只能走「整理成表格」**
- `TOKEN_MISSING / TOKEN_EXPIRED / TOKEN_CONSUMED` ⇒ 凭证不可用（见 `references/70-开场与选路.md` §二）

> `{apiBase}` 与 `{promptToken}` **只有小程序生成的启动语里才有**。手上的启动语没给 ⇒ 按 `NET=no` 处理。
> 🔴 **握手只能做一次**（凭证校验通过即当场注销）。
> 若 `probe_capability.py` 输出了 `NET=` 一行，以它为准。

### `NET` 与 `LEVEL` 的组合

| | `NET=yes` | `NET=no` |
|---|---|---|
| **LEVEL A / B** | ✅ 两条路都能走 | 只能整理表格（xlsx） |
| **LEVEL C** | 只能整理表格（csv） | 只能整理表格（csv） |
| **LEVEL D** | 只能 Markdown 表格 | 只能 Markdown 表格 |

### `NET=no` 时怎么办（**不强制换工具**）

1. 照 `references/70-开场与选路.md` 的话术，**只给「整理成表格」**这一条路；
2. **顺带告知**可以换 **豆包（记得开「工作模式」）** 或 **Kimi** 来一步到位；
3. **不要**因为老师不换就摆烂 —— 表格路线是**能完成任务的**，只是多一步上传。

## 二·补2 · 仓库打不开时的备用地址

本仓库主地址是 GitHub 的 `raw.githubusercontent.com`，**国内部分网络打不开**。

- 打不开时的处理：**用启动语里给的地址**（若启动语给了 Gitee 镜像，就用镜像）；
- 两者都打不开 ⇒ **改用「模板 2」**：把 `assets/元提示词.md` 当附件上传给 AI（不依赖网络）。
- 🔴 **不许因为"读不到仓库"就凭记忆编规则** —— 读不到就照实说，让用户改用附件。


## 三、四档模式（严格按顺序，不得越级）

| LEVEL | 判定 | 产出 | 为什么 |
|---|---|---|---|
| **A** | **能生成 `.xlsx`** **且** 拿得到模板 | `.xlsx`：照模板填数据行 | 模板自带样式/合并/说明，**保真度最高**，最稳 |
| **B** | **能生成 `.xlsx`**，但拿不到模板 | `.xlsx`：按 `30-产物规格.md` 自建 | 样式需自己写全，成本高一点，但结果仍可导入 |
| **C** | 只能产出**文本文件**（写不了 xlsx） | `.csv` | 系统**支持 CSV 导入**，是可靠的退路 |
| **D** | 产出**不了任何文件** | 对话里输出 Markdown 表格 + 另存指引 | 只能如此；此时**必须如实说明**，不要假装给了文件 |

> **判定看的是"你最终能产出什么"，不是"你会不会跑代码"。**
> 会跑代码但环境里装不上库 ⇒ 按 C/D 算；不会跑代码但有平台自带的文件生成 ⇒ 照样算 A/B。

### 顺位的理由

**稳定度优先**：xlsx 走的是系统官方模板（表头、说明、样式全对）；
CSV 走的是纯文本，没有样式但**列结构与 xlsx 完全一致**，系统同样能导入；
Markdown 是最后手段，因为要靠用户手动粘贴、且极易把"说明文字"粘到数据区（→ 假学员）。

## 四、三种"看起来能做"其实不行的情况

1. **能跑代码但沙箱不让写文件** → 别硬试，直接降到 C（或 D）。
2. **能下载文件但下不到仓库**（无外网）→ 若本地有模板走 A，否则走 B/C。
3. **能输出 Markdown 但用户要"文件"** → 走 D，并明确告诉用户"我这边不能生成文件，你可以把它贴进 Excel 再另存为 .xlsx"。

## 五、向用户怎么表达（LEVEL=D 时）

> 我这边不能生成文件。请把下面这张表**整段复制**到 Excel 里（从第一行"学员姓名"开始），
> 另存为 `.xlsx` 或 `.csv`，再到「老生录入」里导入。
> ⚠️ 下面表格之后的内容（包括我写的说明）**不要一起复制进去**。

最后一句很重要——见 `20-数据规范.md` 的"假学员"红线。
