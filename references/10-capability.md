# Capability and tiers (Step 2)

## 1. Why self-assess first

The same prompt behaves very differently across AIs:

- some run code and can hand the user a downloadable file → **xlsx is possible**;
- some only emit text → **Markdown table only**;
- some can write files but cannot install libraries → **fall back to CSV, which also imports**.

**Know your capability before choosing a path** — do not promise "I'll generate an Excel file" and then deliver a block of text.

## 2. How to self-assess

### Run the probe if you can (optional, **not required**)

> 🔴 **This skill is text-first.** `scripts/` is an **optional accelerator** —
> use it if it runs (cheaper, higher fidelity); **not running it never blocks delivery.**
> Produce the output from the written spec instead.

```bash
python3 scripts/probe_capability.py
```

Sample output:

```json
{ "can_run_code": true, "can_write_file": true, "has_openpyxl": false,
  "template_local": true, "template_reachable": false }
VERSION=1.3.0
LEVEL=A
建议=走 A：用 assets/ 里的模板 → scripts/build_xlsx.py 填数据 → 交付 .xlsx
```

**Only the `LEVEL=` line matters.**

### Cannot run the script: three manual questions

1. **Can I execute code?** (Python? a code-execution tool?)
2. **Can I produce a file the user can download?** (not just print content into chat)
3. **Can I obtain the template from `assets/`?** (is the repo local? can I download the raw link?)

---

## 2a. Second check: `NET` (decides whether you can write directly)

`LEVEL` only answers "**what can I produce**". An **independent** capability also matters:
**can you actually issue an HTTP POST?**

> Reading a web page ≠ sending a request. Many AIs can open a link but have **no way to POST anything outward**.

### How to test it (one call: the opening handshake)

```bash
curl -s -X POST "{handshakeUrl}" \
  -H "Content-Type: application/json" -d '{}'
```

| Result | Meaning |
|---|---|
| Response contains `sessionId` | **`NET=yes`** → the write path is available |
| Cannot run / errors / no response | **`NET=no`** → **table path only** |
| `TOKEN_MISSING` / `TOKEN_EXPIRED` / `TOKEN_CONSUMED` | credential unusable — see `references/70-opening.md` §2 |

> `{handshakeUrl}` exists **only** in starter prompts generated by the mini-program.
> Not present ⇒ treat as `NET=no`.
> 🔴 **Handshake exactly once** (the credential is burned on success).
> If `probe_capability.py` printed a `NET=` line, that line wins.

### `NET` × `LEVEL`

| | `NET=yes` | `NET=no` |
|---|---|---|
| **LEVEL A / B** | ✅ both paths | table only (xlsx) |
| **LEVEL C** | table only (csv) | table only (csv) |
| **LEVEL D** | Markdown table only | Markdown table only |

### When `NET=no` (never force a tool switch)

1. Use the wording in `references/70-opening.md` and **offer only "produce a table"**;
2. **Also mention** that **Doubao (with "Work mode" on)** or **Kimi** can do it in one step;
3. **Do not** half-heart the job if the teacher stays put — the table path **completes the task**,
   it just needs one extra upload.

## 2b. Mirror addresses when the repo is unreachable

This repo's primary host is GitHub's `raw.githubusercontent.com`, which **some networks in mainland China cannot reach**.

- If unreachable: **use the address given in the starter prompt** (if it supplied a Gitee mirror, use the mirror);
- If both fail ⇒ **switch to "Template 2"**: hand `assets/meta-prompt.md` to the AI as an attachment (no network needed).
- 🔴 **Never invent rules from memory because the repo could not be read.** Say so and ask the user to use the attachment.

## 3. The four tiers (strict order, no skipping upward)

| LEVEL | Condition | Output | Why |
|---|---|---|---|
| **A** | **Can produce `.xlsx`** **and** can obtain the template | `.xlsx`: fill the template's data rows | template carries styling / merges / notes — **highest fidelity**, safest |
| **B** | **Can produce `.xlsx`** but cannot obtain the template | `.xlsx`: build per `references/30-output-spec.md` | styling must be written out manually, costlier, still importable |
| **C** | Can only produce **text files** (no xlsx) | `.csv` | the system **accepts CSV** — a reliable fallback |
| **D** | **Cannot produce any file** | Markdown table in chat + save-as instructions | only option; **must state it plainly**, never pretend a file was given |

> **The test is "what can you actually produce", not "can you run code".**
> Can run code but the sandbox forbids writing files ⇒ counts as C/D.
> Cannot run code but the platform has built-in file generation ⇒ still counts as A/B.

### Why this order

**Fidelity first**: xlsx follows the official template (header, notes, styling all correct);
CSV is plain text — no styling, but its **column structure is identical to xlsx** and the system imports it the same way;
Markdown is the last resort, because the user must paste manually and it is very easy to paste
"explanatory text" into the data region (→ fake students).

## 4. Three cases that look possible but are not

1. **Can run code but the sandbox blocks file writes** → do not fight it, drop to C (or D).
2. **Can download files but cannot reach the repo** (no external network) → A if the template is local, else B/C.
3. **Can emit Markdown but the user wants "a file"** → take D and say plainly:
   "I cannot generate files here; paste this into Excel and save as .xlsx."

## 5. Wording to the user at LEVEL=D

> 我这边不能生成文件。请把下面这张表**整段复制**到 Excel 里（从第一行"学员姓名"开始），
> 另存为 `.xlsx` 或 `.csv`，再到「老生录入」里导入。
> ⚠️ 下面表格之后的内容（包括我写的说明）**不要一起复制进去**。

That last line matters — see the "fake student" rule in `references/20-data-spec.md`.
