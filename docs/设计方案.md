# 设计方案

## 一、要解决的问题

老师手上有一堆杂乱的学员信息，需要变成能导进教务系统的表。但：

1. **老师不会发给同一个 AI**：可能用 Kimi、豆包、通义、ChatGPT……能力天差地别；
2. **能力差的 AI 会"假装"生成了 Excel**：最后只给一段文字，老师白折腾；
3. **规范容易走样**：不同 AI 生成的表头/列序/说明文字各不相同 → 数据进不去，还极难排查；
4. **规则会变**（比如"剩余课时允许负数"是后来定的口径），散落的提示词副本会过期。

## 二、设计目标

| 目标 | 做法 |
|---|---|
| 任何 AI 都能用 | **能力阶梯**：先自检，再从最稳的路径往下退 |
| 结果不走样 | **单一真源**：列结构、校验口径只写一份，产物由脚本生成 |
| 不假装成功 | LEVEL 决定输出形态；产出不了文件就说清楚 |
| 规则可迭代 | **版本化**：git tag + 版本化 raw 链接 |
| AI 别一次吞太多 | **渐进式披露**：主文件只给指针，按需加载 |

## 三、整体结构

```
                    ┌──────────────────────────────┐
   老师把仓库地址 →  │  SKILL.md（唯一入口 / 6 步流程）│
   + 这段话说给 AI   └──────────────┬───────────────┘
                                   │ 按 6 步走
                    ┌──────────────▼───────────────┐
                    │ 第2步：能力自检               │
                    │ scripts/probe_capability.py  │
                    └──────────────┬───────────────┘
                                   │ LEVEL=A/B/C/D
        ┌──────────────┬───────────┴────────┬──────────────┐
        ▼              ▼                    ▼              ▼
      A 填模板      B 从零生成            C 出 CSV       D 出 Markdown
   build_xlsx.py  30-产物规格.md     build_csv.py   元提示词.md
        └──────────────┴────────────────────┴──────────────┘
                                   │
                    ┌──────────────▼───────────────┐
                    │ 单一真源：20-数据规范.md      │
                    │ （必填/成对/负数/一致性/红线） │
                    └──────────────────────────────┘
```

## 四、能力阶梯（为什么是这个顺序）

| LEVEL | 条件 | 产出 | 稳定度 |
|---|---|---|---|
| A | 能跑代码 + 有模板 | xlsx（填官方模板） | ★★★★★ 样式零漂移 |
| B | 能跑代码 + openpyxl，无模板 | xlsx（从零生成） | ★★★★ 样式要自己写全 |
| C | 能写文件，出不了 xlsx | CSV | ★★★★ 无样式，但结构与导入逻辑一致 |
| D | 出不了文件 | Markdown 表格 | ★★ 靠用户手动粘贴，风险最高 |

**关键前提**：教务系统**同时支持 `.csv` / `.txt` 导入**（2026-10-13 上线），
所以 C 档是"真的能用"，而不是凑合 —— 这让整个降级链条变得可靠。

**为什么 A 优于 B**：A 是在官方模板副本上插入数据行，表头、说明、样式、合并全都不用重写，
**结构不可能漂移**；B 是从零拼，每一处样式都要有人负责写对。

## 五、渐进式披露

AI 进仓库只读 **`SKILL.md`（唯一入口）**，然后按 LEVEL **只**加载需要的 2 个文件：

- 每次都读：`references/20-数据规范.md`（校验口径）
- A：+ `scripts/build_xlsx.py`
- B：+ `references/30-产物规格.md`
- C：+ `scripts/build_csv.py`
- D：+ `assets/元提示词.md`

避免一次性塞进所有规则 → 省上下文、也降低"读到过期内容"的概率。

## 六、版本策略

- `VERSION` 文件 + `CHANGELOG.md` + **git tag `vX.Y.Z`**
- README 里给**版本化 raw 链接**（把 tag 写进 URL），保证"同一会话内读到的一直是同一版"
- 版本语义：**改规范/规则 → 升 minor**；改文案/错字 → 升 patch

## 七、红线（为什么写三遍）

系统解析时**只跳过三种行**：空行 / 第 1 列以「示例」开头 / 第 1 列正好是「必填」。
⇒ **表头行以下任何非空文字都会被当成学员姓名建档**。

这条红线在 `SKILL.md`（红线 4）、`references/20-数据规范.md`、`references/30-产物规格.md` 里各写了一遍 ——
因为它是**最容易犯、后果最脏**的错误（会静默建出一个"叫备注：…的学员"），
历史上线上提示词里就有一条"在表格下面用「备注：」说明问题"的指令踩中了它。

## 八、为什么脚本只用标准库

`build_xlsx.py` 刻意**不依赖 openpyxl**：只做"复制模板 + 在 XML 里插数据行"。
原因：目标 AI 的执行环境千奇百怪，openpyxl 经常装不上；
而**本仓库自带模板**，所以"改 XML"这条路零依赖、成功率最高。

## 九、目录职责

| 路径 | 职责 | 谁读 |
|---|---|---|
| `SKILL.md` | **唯一入口：6 步流程 + 红线 + 目录** | AI |
| `README.md` | 人类门面（按角色进入 + 老师用法 + 维护须知） | 人 |
| `references/` | AI 按需加载的说明（10 能力 / 20 数据 / 30 产物 / 40 写入 / 50 错误 / 60 安全 / 70 选路） | AI 按需 |
| `assets/` | 给老师的产物：启动语 / 隐蔽版 / 元提示词 / 官方模板 | 人 + AI（A 档） |
| `scripts/` | 自检与生成脚本（**可选加速器**） | AI |
| `docs/` | 设计说明 + 线上模板修改清单 | 维护者 / 运营 |
